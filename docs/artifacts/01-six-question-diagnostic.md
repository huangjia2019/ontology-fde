# 第 1 站：检查退款方案中的业务定义

“接入客服知识库和退款 API”描述了数据和工具，但还不能决定某笔退款应该怎样处理。例如，查询返回的订单必须属于申请人，自动批准必须符合财务政策，失败后必须保留能够继续办理的记录。可以用下面六项检查方案中的业务定义。

| 检查项 | 云帆项目中的具体定义 | 实现位置 |
|---|---|---|
| 执行主体 | `agent.cs.refund.001` 以自身身份执行，不借用主管账号 | [身份配置](../../config/identity/refund_agent.yaml) |
| 处理对象 | 申请关联客户、订单和订单项，三者必须一致 | [对象与状态](../../config/ontology/) |
| 业务动作 | 批准、转人工或补证，均有对应前提与效果 | [动作契约](../../config/actions/) |
| 判断依据 | ERP 查无记录记为发票未知，交财务核实是否开票 | [规则资产](06-rule-assets.md) |
| 授权范围 | 自动批准限额 500 元，禁止修改申请金额 | [权限配置](../../config/policies/permissions.yaml) |
| 失败处理 | 付款指令失败进入待付款状态，生成财务任务 | [评估与复盘](09-evaluation-audit-and-incident-replay.md) |

## 核对身份与业务事实

```bash
python3 run.py summary
python3 run.py identity
```

`summary` 返回来源和对象概况，`identity` 返回身份及能力范围。运行 `python3 run.py inspect YF-R-0311` 可以进一步核对这笔申请的对象引用和来源记录。

如果申请、订单和商品的引用关系错了，应修改数据关联；如果发票未知仍被批准，应检查来源映射和退款策略；如果未授权主体能执行，则检查授权路径。问题不同，修改位置也不同。
