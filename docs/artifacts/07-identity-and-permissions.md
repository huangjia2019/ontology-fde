# 第 7 站：条件都满足，也要问谁有权执行

`YF-R-0500` 的金额和其他业务条件全部通过。退款 Agent 可以批准这笔申请，未登记的营销 Agent 却不能执行同一个动作。

```bash
python3 run.py run YF-R-0500 --mode write --actor agent.marketing.unknown
python3 run.py checkpoint 7 --check
```

结果应为 `permission_denied`，命中 `G-ACTOR`；前后状态都为 `pending_review`，不创建付款指令。任务信封标记 `rejected_actor_mismatch`，调用轨迹中有被拦截的 `action.enforce_write_guard`。

## 业务符合条件，与调用者获准执行

| 执行主体 | 申请 | 结果及原因 |
|---|---|---|
| 已授权退款 Agent | 500 元，条件全部通过 | 批准并创建付款指令 |
| 未登记营销 Agent | 同一笔 500 元申请 | `G-ACTOR` 拒绝，不改变状态 |
| 已授权退款 Agent | 500.01 元，其他条件通过 | `G-AMOUNT` 转人工，等待人工批准后再进入付款流程 |

主体检查 `G-ACTOR` 决定这个主体能否使用动作，金额检查 `G-AMOUNT` 决定这笔申请是否超过自动批准上限。所有助手共用一个账号时，记录里的 `actor` 都相同，仅凭它分不清是哪个助手执行的；撤销共用凭据还会影响其他助手。即使身份可信，也要检查金额等业务条件，才能决定是否批准这笔申请。

## 权限配置的六个维度

查看[权限配置](../../config/policies/permissions.yaml)，并与[身份](../../config/identity/refund_agent.yaml)及[动作契约](../../config/actions/approve_refund_small.yaml)对照。

| 维度 | 本项目约定 | 要请谁确认 |
|---|---|---|
| 数据 | 读取退款所需对象，不读取完整银行卡号、证件号和营销画像 | 数据负责人、安全 |
| 工具 | 查询事实、评估规则、经控制创建指令和人工材料 | 系统负责人 |
| 动作 | 小额批准、转人工、补证；禁止修改申请金额 | 客服主管、财务 |
| 条件 | 金额、证据、风控及其他退款条件通过 | 业务规则负责人 |
| 时间 | 配置声明授权起止时间 | 安全、授权负责人 |
| 环境 | 仅声明 `demo`、`gray`，`production_write: false` | 发布与安全负责人 |

## 哪些已经运行，哪些还需要集成

当前执行器检查主体、动作授权、业务条件、任务信封期限和状态转换，并在决策记录中保存执行结果。`--actor` 接收身份字符串，不验证调用者凭据。权限配置中的数据清单、工具清单、授权时间窗和环境限制还没有逐项执行；任务信封的四小时期限是另一项已实现的检查，不能替代凭据有效期检查。

`production_write: false` 记录了“不授权生产写入”的要求。当前程序操作的是内存样例，没有接入企业写接口。将来接入时，还要在网关、凭据或目标服务中落实环境限制，拒绝未获生产授权的请求。

金额越界的比较命令：

```bash
python3 run.py run YF-R-0501 --mode write
```

真实接入时，认证服务应提供可信主体，动作网关检查授权，业务服务验证金额、状态等前提。其他调用方可以绕过模型直接请求业务接口，所以禁止修改金额的要求必须由服务端检查；提示词中的约定用于指导模型选择动作。
